# Questboard

Уеб платформа, която превръща участието в училищния живот в игра. Учителите
пускат мисии, учениците ги изпълняват и получават XP, нива и монети, а с
монетите купуват привилегии. Вграденият асистент дава подсказки, помага на
учителите да съставят мисии и отговаря на справки по разписанието.

## Архитектура

Системата е от отделни части, които общуват по мрежата:

```
Браузър ──HTTP──▶ Основно API (Django) ──SQL──▶ База данни (SQLite / MySQL)
                        │
                        └──HTTP + таен ключ──▶ Асистент (FastAPI) ──HTTPS──▶ Езиков модел
```

- **Уеб клиент (браузърът)**: страниците се генерират от Django шаблони (HTML
  и CSS). Чатът с асистента е на обикновен JavaScript и говори с REST API-то.
- **Основно API (Django + Django REST Framework)**: страниците, REST API-то и
  всички правила на играта. Само то пише в базата и проверява правата.
- **Асистент (FastAPI)**: отделна програма. Ключовете за езиковите модели
  стоят само тук. Приема заявки само от Django и слуша само на `127.0.0.1`.
  Не чете базата: Django му праща само нужните данни, без лични данни на ученици.
- Ако асистентът е спрян или изключен от администрацията, платформата
  продължава да работи без него.

## Структура на папките

```
backend/                Основно API (Django)
  questboard/           настройки и главни адреси
  accounts/             потребители, роли, класове, гилдии
  missions/             мисии и заявки
  economy/              XP, монети, нива, магазин, настройки на играта
  timetable/            разписание: часове, предмети, кабинети
  assistant_bridge/     връзка с асистента и журнал на ползването
  notifications/        известия в сайта (звънчето горе вдясно)
  badges/               значки за постижения
  quizzes/              тестове на гилдиите
  api/                  REST API (JSON)
  web/                  страниците (Django шаблони)
  templates/, static/   HTML шаблони и CSS
assistant_service/      Услуга на асистента (FastAPI)
  main.py               адресите: /hint, /mission-draft, /query/plan, /query/answer
  logic.py              подготовка на заявките към модела и проверка на отговорите
  prompts.py            инструкциите към модела
  providers/            OpenAI, Gemini и Claude зад общ интерфейс
start.py                пуска цялата система с една команда
run_tests.py            пуска всички тестове с една команда
.env.example            пример за файла с тайните и портовете
```

## Инсталиране (Windows, PowerShell)

Нужен е Python 3.12 или по-нов.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

Отворете `.env` и сменете `DJANGO_SECRET_KEY` и `ASSISTANT_TOKEN` с дълги
случайни низове. Случаен низ се прави така:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

После създайте базата и първия администратор:

```powershell
cd backend
python manage.py migrate
python manage.py createsuperuser
cd ..
```

Примерни данни (класове, мисии, разписание и тестов акаунт за всяка роля,
само с измислени хора) се зареждат така, след като сложите `DEMO_PASSWORD` в `.env`:

```powershell
cd backend
python manage.py seed_demo
cd ..
```

Тестовите акаунти са `admin@questboard.test`, `uchitel@questboard.test` до
`uchitel4@questboard.test` и `uchenik@questboard.test`, `uchenik2@questboard.test`
до `uchenik36@questboard.test`.

За MySQL вместо SQLite: `pip install -r backend/requirements-mysql.txt` и
`DB_ENGINE=mysql` с данните за базата в `.env`.

## Стартиране

```powershell
python start.py
```

- Questboard: http://127.0.0.1:8000
- Администрация: http://127.0.0.1:8000/admin/
- Документация на API-то: http://127.0.0.1:8000/api/docs/

Спиране: **Ctrl+C**. Портовете се сменят от `.env` (`DJANGO_PORT`, `ASSISTANT_PORT`).

Името и логото на училището се качват от администрацията → „Настройки на
играта“ → „Училище“ (PNG, JPG или WebP до 1 MB). Логото е собственост на
училището, затова не е в GitHub и не е под лиценза GPL; файлът стои само на
сървъра (папка `backend/media/`).

Сайтът има светла и тъмна тема (бутонът горе вдясно). По подразбиране следва
настройката на устройството, а изборът се запомня в браузъра.

## Публикуване

1. В `.env` на сървъра: `DJANGO_DEBUG=False`, нов `DJANGO_SECRET_KEY`,
   `DJANGO_ALLOWED_HOSTS` с домейна, `DJANGO_CSRF_TRUSTED_ORIGINS` с пълния
   адрес (напр. `https://questboard.example.bg`) и `DB_ENGINE=mysql` с данните
   за базата.
2. Ако пред приложението има прокси сървър с HTTPS (nginx или хостинг):
   `DJANGO_BEHIND_PROXY=True`, а когато HTTPS работи – `DJANGO_SSL_REDIRECT=True`
   и `DJANGO_HSTS_SECONDS=31536000`.
3. Стартиране:

```powershell
python start.py --production
```

Това прави миграциите, подготвя статичните файлове (WhiteNoise), проверява
настройките за сигурност (`manage.py check --deploy`) и пуска сървъра waitress
вместо сървъра за разработка. Асистентът остава достъпен само локално.

## Асистентът

Асистентът работи с един доставчик по ваш избор: **Claude, Gemini или OpenAI**.
Резервни доставчици няма: ако избраният модел не отговори, потребителят
получава ясно съобщение защо (невалиден ключ, непознат модел, претоварен
модел, бавен отговор), а платформата продължава да работи.

1. В `.env` сложете ключа за доставчика (`ANTHROPIC_API_KEY`,
   `GEMINI_API_KEY` или `OPENAI_API_KEY`) и рестартирайте `start.py`.
2. В администрацията → „Настройки на играта“ изберете доставчика. Полето
   „модел“ може да остане празно: тогава се ползва препоръчаният
   (`claude-opus-5-5`, `gemini-3.5-flash-lite` или `gpt-5-mini`).
3. Запазете и натиснете **„Провери асистента“** горе вдясно. Бутонът праща
   една кратка заявка към модела и показва отговора и времето или точната
   грешка (с оригиналния текст на доставчика).

Какво може:

- **Подсказка (Ф10)**: ученикът харчи Hint Token и получава насока по мисия.
  Ако моделът не отговори, токенът не се харчи.
- **Чернова на мисия (Ф11)**: учителят описва идея и асистентът попълва
  формата. Нищо не се публикува без учителя.
- **Справки (Ф17, Ф18, Ф22, Ф14)**: моделът само избира коя справка да се
  изпълни (извикване на функции). Django я изпълнява с правата на питащия.
  Имената на учителите се заменят с кодове, преди да отидат към модела.
- Всяко ползване се записва в журнала. Има дневен лимит на потребител.

Контролните случаи (20 броя) се пускат срещу избрания модел. С `--provider`
се пробва друг доставчик, а с `--provider all` всеки, за който има ключ:

```powershell
cd backend
python manage.py evaluate_assistant
```

Резултатите се записват в `docs/assistant-evaluation.md`
(или `docs/assistant-evaluation-<доставчик>.md`).

## Администрация

В администрацията (`/admin/`) влиза само ролята „администратор“. Учителите
работят изцяло от сайта: мисии, заявки, привилегии, класация, справки и асистент.

Началната страница на администрацията е табло: брой ученици, активни тази
седмица, чакащи заявки и XP за седмицата, графика на потвърдените мисии за
последните 8 седмици, XP по гилдии, най-изпълняваните мисии и ползването на
асистента по модел. Графиките са HTML и CSS без библиотеки и могат да се видят
и като таблица.

## Потребители

Няма свободна регистрация: акаунтите се създават от администратора, за да са в
платформата само истински ученици и учители с правилните роли. Много хора
наведнъж се внасят от CSV: администрация → Потребители → „Внеси от CSV“.
Първият ред е:

```
имейл,име,фамилия,роля,псевдоним,клас,гилдия
```

Пример: [backend/accounts/sample/potrebiteli_primer.csv](backend/accounts/sample/potrebiteli_primer.csv).
Всеки нов потребител получава временна парола, която се показва само веднъж
(и може да се свали като CSV), и трябва да я смени при първия вход.

### Псевдоними

В класациите се виждат само псевдоними. Ученикът сменя своя от „Профил“: от 3
до 20 знака (букви, цифри, интервал, „-“ и „_“), да не е зает (без значение
главни или малки букви) и да не съдържа истинското му име или забранена дума.
Смяната е най-много веднъж на 30 дни. Броят дни и списъкът със забранени думи
са в „Настройки на играта“ → „Псевдоними“. Всяка смяна (и от администратора)
се пази в историята, която се вижда на страницата на ученика в администрацията.

### Защита на входа

След 5 грешни пароли за един имейл входът с него спира за 15 минути – дори с
вярна парола. От един IP адрес се позволяват 4 пъти повече грешки, защото в
училище много ученици са зад един рутер. Двете числа се сменят от „Настройки
на играта“ → „Защита на входа“. Неуспешните опити са в „Журнали“ →
„Неуспешни входове“, откъдето администраторът може да отключи някого веднага.
Ако сайтът е зад обратен прокси сървър, задайте `DJANGO_BEHIND_PROXY=True`, за
да се вижда истинският IP адрес на потребителя.

## Награди от учителя

Освен с мисии учителят може да награди ученик и от страницата „Награди“:

- **Бонус XP** със задължителна причина, например „Помощ при концерта“. По
  подразбиране е най-много 50 XP наведнъж и 150 XP на седмица от един учител.
  Лимитите са в „Настройки на играта“ → „Бонус XP от учител“ (0 – изключено).
  Бонусът минава през същите правила като мисиите: монети по курса и
  седмичния лимит, ново ниво, значки и известие до ученика. В журнала е
  отбелязан като бонус. Монети и привилегии директно не се дават, за да не
  се заобикаля седмичният лимит.
- **Значка, дадена ръчно**: значки с правило „Дава се от учител“, например
  „Звезда на седмицата“, „Отборен играч“ и „Златна идея“ (примерни, сменят се
  от администрацията). Учениците ги виждат едва когато ги получат.

Има и API: `POST /api/rewards/bonus/` и `POST /api/rewards/badge/` (само за учители).

**Отмяна.** Ако нещо е дадено по грешка, учителят може да го отмени до 7 дни
(сменя се от настройките), а администраторът – винаги. Причината е задължителна
и ученикът я вижда в известие.

- Бонус XP: от „Награди“ → „Отмени“.
- Потвърдена заявка: от страницата на мисията → „Отмени“. Заявката става
  отказана с причината и ученикът може да я подаде пак.
- Значка, дадена ръчно: от „Награди“ → „Отмени“. Автоматичните значки не се отнемат.
- В администрацията: „Движения на XP“ → „Отмени избраните награди“ и
  „Получени значки“ → „Отнеми избраните значки“.

Нищо не се изтрива: отмяната е ново движение с минус, което сочи към
отмененото, затова в журнала се виждат и двете. Връщат се и монетите, дадени
заради това XP. Ако вече са похарчени, сметката става на минус и ученикът не
може да пазарува, докато не спечели нови. Нивото може да падне, а
автоматичните значки остават.

## Доказателства със снимки и файлове

Към заявката ученикът пише текст (описание или връзка) и/или прикачва до 3
файла (снимки, PDF, Word, Excel или PowerPoint), до 5 MB всеки. Броят и размерът се
сменят от „Настройки на играта“ → „Доказателства“ (0 файла – само текст).
Видео не се качва, защото бързо пълни диска: слага се като връзка в текста.

- Проверява се самото съдържание, а не разширението: снимката трябва да се
  отвори, а PDF-ът да започва с `%PDF-`. Всичко друго се отказва.
- Всяка снимка се записва наново като JPEG до 1600 px. Така се махат скритите
  данни (EXIF), например GPS мястото на снимката, а файлът става малък.
- Файловете са в `backend/media/evidence/` със случайни имена и **не са
  публични**: показват се само на ученика, отбора му, учителите, които проверяват мисията, и администратора
  (`/evidence/<номер>/`), без да могат да изпълняват скриптове.
- Администраторът вижда и може да изтрие файловете от „Заявки“. При изтриване
  или при нова заявка след отказ се трие и самият файл от диска.
- При публикуване папката `backend/media/` трябва да се пази между версиите и
  да влиза в резервните копия, защото в нея са логото и доказателствата.

## За учениците

- **Две гилдии**: ученикът е в най-много две, едната е основна (`backend/accounts/guilds.py`). От нея са
  темата на сайта и цветът на аватара, а XP се брои само за нея в класацията на гилдиите. Основната
  се сменя веднъж на 30 дни от „Гилдии“, а напусналият се връща само с входен тест.
- **Отговорници на гилдиите**: администраторът ги избира от „Гилдии“ (един или повече учители). Ученикът
  ги вижда на картата на гилдията, а учителят в „Гилдии“: кой за какво отговаря и, за своите гилдии,
  членовете, тестовете и последните опити. Правата не се променят: мисии и тестове прави всеки учител.
- **Аватар**: рисува се от сървъра като шарка 5×5 в цвета на гилдията, без
  снимки (`backend/web/avatars.py`). От „Профил“ ученикът може да поиска нова шарка.
- **Мисиите като в игра**: бронзови, сребърни и златни карти според XP, етикет
  „Нова“, „остават N дни“ и колко ученици са я изпълнили.
- **Класация „Тази седмица“** освен общата, с подиум и избор „Топ 10“ или „Топ 100“. В общата стрелките показват с колко
  места е мръднал всеки от началото на седмицата, а ученикът винаги вижда своя ред.
- **Серии**: поредни седмици с изпълнена мисия, със значки за 3, 5 и 10 седмици.
- **„Браво!“**: при ново ниво или значка ученикът вижда голяма карта веднъж
  (без анимация, ако устройството е настроено на по-малко движение).
- **Неща за профила в магазина**: титли до псевдонима и рамки на аватара.
  Те са само за външен вид, не влияят на ученето и не се отбелязват от
  учител. Ученикът избира кои да се виждат от „Профил“. Добавят се от
  администрацията („Игра“ → „Магазин“, вид „Титла“ или „Рамка на аватара“).
- **Като приложение на телефона**: сайтът може да се добави към началния екран
  (`/manifest.webmanifest`, `/sw.js`). На малък екран менюто за ученици е
  долу. Service worker-ът не пази страници с данни – само показва „Няма
  връзка“, когато интернетът липсва.

- **Отключване по ниво**: титлите и рамките имат поле „от ниво“; предмет с „печели
  се само от мисия“ не се продава.
- **Асистентът** е в прозорче долу вдясно на всяка страница. Разговорът се помни само
  в отворения раздел и се изчиства при изход. Последните три въпроса с отговорите им се
  пращат с новия, за да разбира „а в четвъртък?“. Знае мисиите, магазина, значките, класацията,
  правилата и (за учителя) чакащите заявки: `backend/assistant_bridge/site_tools.py`. Бутоните под
  отговора са от сървъра. Имена и псевдоними на ученици не се пращат към модела.

## Гилдии, отбори и награди

- **Гилдиите са по интереси**: Помощници, Артисти, Техничари, Изследователи,
  Спортисти и Организатори. Имената се сменят от администрацията; цветът и иконата
  са в полето „цвят и икона“.
- **Отборна мисия**: капитанът подава заявката и изписва псевдонимите на
  съотборниците. Учителят решава веднъж и всеки получава пълната награда. Всеки
  е най-много в един отбор за мисия и може да напусне, докато заявката чака.
- **Награди само от мисия**: значка с правило „Дава се от мисия“ и предмет. При
  отмяна на потвърждението се връщат (освен вече предадените).
- **Заместници**: авторът на мисията избира кои учители също могат да проверяват.
- **Награди от външни контрибутори** („Игра“ → „Външни контрибутори“ и „Магазин“): билети, книги и
  курсове с ограничен брой. Купуват се с монети или се печелят от мисия. Всяка награда има
  **отговорник** (за всяка може да е различен): само той и администраторът я отбелязват като
  предадена, а ученикът вижда от кого ще я получи. Ако отговорникът вече не е активен, предава всеки учител.
- **Файлове**: учителят прикачва указания към мисията, а ученикът – доказателства:
  снимки, PDF, Word, Excel и PowerPoint (без макроси).

## Тестове на гилдиите и домашни

- **Входен тест** (минава се с 80%): който го мине, влиза в гилдията. **Месечен тест**: само за
  членовете, веднъж на месец, дава XP. Настройките са в самия тест („Тестове“ в менюто на учителя).
- **Само пред учител**: учителят пуска теста и казва код, който важи избраните минути. Без код опит
  не започва, а след 10 грешни кода ученикът чака 10 минути.
- **Време**: мери се на сървъра (`backend/quizzes/services.py`). Въпросите са разбъркани, идват един по
  един, без връщане; закъснял отговор е грешен. Видове: избор, подреждане на стъпки, писмен отговор.
- Учителят вижда резултатите на живо и колко пъти ученикът е напускал страницата, и може да анулира опит
  (XP и гилдията се връщат). Това затруднява преписването, но не го изключва.
- **Въпроси от асистента** са чернови и не влизат в теста без одобрение.
- **Домашна** („Мисии“ → „Нова домашна“): само за избрани класове, с предмет вместо гилдия, до
  „най-много XP за една домашна“ от настройките. XP е за приета работа и не е оценка.

## Вид на сайта

Два комплекта, от долната лента или профила: „Училищен“ и „Геймърски“ (`backend/static/css/gamer.css`).
Изборът е в браузъра. И в двата всяка гилдия, учителите и администраторът имат своя тема: цвят, форма
на картите и шарка на фона (`backend/static/css/themes.css`). Ученик без гилдия и гостите виждат
общата горчична тема.

## Проверка на системата

Администрация → „Проверка на системата“ намира проблеми (заявки без проверяващ,
изтекли мисии, изчерпани предмети и други) и предлага поправка. Правилата са в
`backend/questboard/diagnostics.py`. Асистентът само обяснява кое е най-важно – вижда
вида и броя на проблемите, без имена. Нищо не се променя без бутон, а всяка поправка
се записва в журнала.

## Известия и значки

Ученикът получава известие (звънчето горе вдясно), когато учителят потвърди
или откаже заявката му, когато мине на ново ниво и когато получи значка.
Известията не се пращат по имейл – остават в сайта.

Значките се дават сами, когато ученикът стигне прага си: напр. „Първа мисия“,
„Пет мисии“, „Верен на гилдията“ (5 мисии в една гилдия). Началните значки са
примерни. Администраторът ги променя и добавя нови от „Игра“ → „Значки“ с едно
от правилата: брой мисии, мисии в една гилдия, XP, ниво или покупки. Ученикът
вижда на началната страница всички значки и колко му остава до всяка.

## Условия и поверителност

Страниците „Условия за ползване“ (`/terms/`) и „Политика за поверителност“
(`/privacy/`) са отворени за всички и имат връзки в долната част на сайта и
на входа. Текстът им се сменя от администрацията → „Сайт“ → „Условия и
поверителност“, с прост формат: празен ред – нов абзац, „## “ – заглавие,
„- “ – точка от списък. `[училище]` и `[имейл]` се заменят с името на
училището и имейла за връзка от „Настройки на играта“.

Началният текст е образец, който описва как работи платформата. Преди
публикуване училището трябва да го прегледа и допълни. Ако текстът се
развали, действието „Върни началния текст“ го възстановява.

## Разписание

Разписанието се внася от CSV файл: от администрацията (Разписание → „Внеси
от CSV“) или с `python manage.py import_timetable файл.csv`. Първият ред е:

```
ден,час,начало,край,клас,предмет,учител,кабинет
```

Пример: [backend/timetable/sample/razpisanie_primer.csv](backend/timetable/sample/razpisanie_primer.csv)
(измислени учители). Справките са на страница „Справки“ и работят и без асистента.

## Демо данни

```powershell
cd backend
python manage.py seed_demo       # акаунти, класове, мисии, домашни, външни награди, тестове, разписание
python manage.py seed_activity   # осем седмици активност
```

`seed_activity` добавя потвърдени, чакащи и отказани заявки, отбори, домашни,
решени тестове, бонуси, покупки, титли и значки, за да изглеждат класацията,
сериите и таблото живи на демонстрация. Всяко събитие минава през правилата на
играта в своя ден от миналото ([backend/accounts/demo/story.py](backend/accounts/demo/story.py)).
Хората и контрибуторите са измислени, а снимките към доказателствата са истински, със
свободен лиценз (CC0 или public domain) и без лица; авторите са в
[CREDITS.md](backend/accounts/demo/files/CREDITS.md). Командата отказва да работи, ако в
базата има потребители извън демо домейна.

Ново начало:

```powershell
python manage.py reset_demo
```

Изтрива **всички** акаунти (и администраторите), мисии, заявки, файлове, тестове,
покупки, известия и журнали и зарежда демо данните наново. Пита, преди да изтрие.
Остават настройките на играта, училището и логото, нивата, гилдиите, началните
значки и предмети, текстовете на страниците и разписанието. Няма връщане назад,
затова първо направете копие на базата и на папката `backend/media`. Ако нещо се
счупи по средата, базата остава каквато е била.

За отделна демо база, без да се пипа основната, задайте `DB_SQLITE_PATH` и
`DJANGO_MEDIA_ROOT` преди командите и преди `start.py`.

## Настройки: какво къде е

| В Django admin („Настройки на играта“) | Във файла `.env` |
|---|---|
| курс XP към монети, седмичен лимит, пренасяне на остатъка | портове и адрес на асистента |
| най-много XP за мисия, граници на нивата | връзка с базата данни |
| цени на привилегиите | `DJANGO_SECRET_KEY`, `ASSISTANT_TOKEN` |
| асистентът включен/изключен, доставчик и модел, лимит на заявките | ключовете за езиковите модели |
| име и лого на училището, защита на входа | `DJANGO_BEHIND_PROXY`, HTTPS настройки |

В `.env` са само стойностите, нужни при стартиране, и тайните. Файлът не се
качва в GitHub.
